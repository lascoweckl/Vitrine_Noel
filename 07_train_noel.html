7 — Train de Noël piloté par smartphone

Votre mission

Fiche d’accompagnement — trame volontairement incomplète. Vous devez concevoir, compléter, tester et justifier votre programme. Aucune solution complète n’est fournie.

Depuis un smartphone connecté au réseau Wi-Fi de l’ESP32, créer une page Web permettant de démarrer et arrêter un train miniature, puis de régler sa vitesse si le matériel le permet. Le pilotage doit rester sûr en cas de perte de connexion.

Ce que nous reprenons du projet WALL·E

La chaîne de commande reste la même. Pour le train, un seul moteur suffit dans la version de base : nous n’utilisons pas les commandes gauche/droite du robot.

Bouton HTML → Événement JavaScript → Requête HTTP → Serveur ESP32 → Commande du moteur

Architecture à compléter

Smartphone → réseau Wi-Fi → page HTML/CSS/JavaScript → requête HTTP → ESP32 → interface de puissance → moteur du train

À représenter sous forme de schéma fonctionnel, en distinguant la commande et la puissance.

Travail demandé

  • 1. Dessiner l’interface de commande sur papier.
  • 2. Compléter la page HTML.
  • 3. Programmer les événements JavaScript.
  • 4. Préparer le serveur Web ESP32.
  • 5. Relier la réception des commandes au moteur.
  • 6. Tester la sécurité d’arrêt.

Avant de commencer : matériel et sécurité

Identifier la tension nominale du moteur, le courant maximal et le type de commande de puissance (pont en H, transistor/MOSFET, module moteur adapté).

Ne jamais alimenter directement le moteur depuis une broche GPIO de l’ESP32. Prévoir une masse commune lorsque nécessaire et une alimentation adaptée. Le câblage exact dépend du train utilisé.

Questions de préparation

1. Quelle différence faites-vous entre la partie commande et la partie puissance ?
2. Pourquoi une page HTML ne peut-elle pas alimenter directement un moteur ?
3. Quel comportement attendez-vous si le Wi-Fi est coupé pendant le déplacement ?

HTML décrit les éléments de la page. CSS définit leur apparence. JavaScript gère les interactions. Commencez par une interface minimale, puis améliorez-la.

À comprendre

Un attribut id permet à JavaScript de retrouver un élément précis de la page. La balise button crée un bouton cliquable. L’élément p peut afficher un message d’état.

Vérifications

  • Les deux boutons sont visibles.
  • Les identifiants sont différents.
  • La page est lisible sur smartphone.
  • Le curseur, s’il existe, possède une valeur minimale et maximale.

Question : Pourquoi doit-on utiliser le même identifiant dans le HTML et dans le JavaScript ?

Étape 4 — Sécuriser, tester et expliquer

Une sécurité indispensable

Sur WALL·E, l’ESP32 impose un arrêt si les commandes ne sont plus reçues pendant un délai défini. Pour un train, réfléchissez à une stratégie analogue : arrêt sur demande, mais aussi arrêt automatique si la communication disparaît.

Cette sécurité doit être assurée par l’ESP32, pas seulement par l’affichage Web. Piste de travail : utiliser millis() pour mesurer le temps écoulé depuis la dernière commande valide, sans bloquer la boucle principale avec un long delay(). À vous de définir le délai et la manière de maintenir ou renouveler l’autorisation de marche.
